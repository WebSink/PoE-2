# Gear Analyzer (S5.1)

Детерминированный разбор замены экипировки для персонажа из профиля: можно ли
надеть предмет, что он меняет, чего посчитать нельзя. Все игровые числа берутся
из реального движка Path of Building 2 через `pob-mcp`, а не считаются моделью.

- Пакет: `poe2cc/gear/`
- CLI: `scripts/gear_analyze.py`
- Тесты: `tests/test_gear_*.py` (115 тестов, из них 7 — интеграционные с настоящим PoB2)

## Что модуль делает и чего не делает

Делает:

- читает текущий предмет из **реального** PoB2-экспорта (`data/builds/sinkov-standard.xml`);
- проверяет уровень и атрибуты до расчёта (движок PoB2 этого не делает — см.
  `docs/pob2-limitations.md`);
- считает разницу характеристик на временной копии билда: тот же конфиг монстра,
  тот же набор камней, изменён только один слот;
- показывает сопротивления до и после капа (75%) с учётом штрафа сценария;
- перечисляет потерянные и полученные модификаторы, отдельно — локальную защиту предмета;
- даёт итоговую оценку с формулой по каждому вкладу;
- проверяет, что исходный XML не изменился (sha256 до и после).

Не делает (намеренно):

- не запускает движок для предмета, который персонаж не может надеть;
- не выдумывает числа, если предмет нельзя достоверно воспроизвести в PoB2 —
  в этом случае отчёт переходит в режим `declared_only` и перечисляет ограничения;
- не считает локальную защиту предмета сложением модификаторов;
- не проверяет цены, продавцов и доступность объявления;
- не покупает и не пишет продавцам;
- не имеет UI (это S5.2).

## Уровни достоверности в отчёте

Каждое число помечено источником (`basis`):

| `basis` | Значение |
|---|---|
| `engine` | вывод Path of Building 2 под конфигурацией сценария |
| `declared` | арифметика по объявленным модификаторам предмета |
| `—` + статус `engine_required` | величину нельзя получить без движка |
| `—` + статус `unknown` | данных нет вовсе |

Статус `computed` означает, что число посчитано; `engine_required` и `unknown`
всегда сопровождаются причиной. Отчёт никогда не показывает голое число без
источника.

## Входные данные

1. **Профиль персонажа** — `data/characters/sinkov.json` (schema 2.1.0). Из него
   берутся уровень, атрибуты и сценарий (`calculated.scenarios[*]`).
2. **PoB2-экспорт** — `data/builds/sinkov-standard.xml` (локальный, в Git не входит).
3. **Кандидат** — один из трёх форматов:
   - текст, скопированный в игре (`.txt`/`.item`);
   - JSON с нормализованными свойствами;
   - объект Python (`dict`) при вызове из кода.

### Текст предмета

```
Rarity: RARE
Victory League
Silk Slippers
Item Level: 60
Quality: 0
LevelReq: 36
Energy Shield: 79
+43 to maximum Energy Shield
+21 to maximum Life
```

Разбор понимает: редкость, название, базовый тип, `Item Level`, `LevelReq`,
`Quality`, `Requires: Level N, X Str/Dex/Int`, строки защиты (`Armour:`,
`Evasion:`, `Energy Shield:`), `Implicits: N`, руны и сокеты. Всё, что идёт после
шапки, — модификаторы: распознанные получают эффекты, нераспознанные сохраняются
как `UNKNOWN` вместе с исходным текстом.

### JSON с нормализованными свойствами

```json
{
  "name": "Ураганная спешка",
  "slot": "Boots",
  "base": null,
  "required_level": 45,
  "defences": {"armour": 115, "energy_shield": 34},
  "attribute_requirements": {"strength": null, "dexterity": null, "intelligence": null},
  "mods": [
    {"text": "20% increased Movement Speed"},
    {"stat": "fire_resistance", "value": 14}
  ],
  "declared_totals": {"life": 83},
  "provenance": {"kind": "owner_provided_listing_description"}
}
```

`mods[].stat` + `value` — путь для случаев, когда строка неоднозначна;
`declared_totals` — объявленный итог характеристики (см. ниже).

## Связанные бонусы и двойной счёт

Связанные бонусы (linked) в описании предмета часто уже включены в итоговую
цифру. Если сложить строки и добавить итог, получится задвоение. Правило:

1. Если для характеристики задан `declared_totals`, он **заменяет** сумму строк
   (`basis: declared_total`); строки сохраняются в отчёте для показа.
2. Если итог не задан, используется сумма строк (`basis: declared_modifiers_sum`).
3. Если сумма строк расходится с объявленным итогом, в отчёт попадает
   предупреждение — расхождение видно, а не спрятано.

Отдельно: локальная защита предмета (`Armour: 115`, `Energy Shield: 34`) — это не
модификатор. Она показывается в блоке «Локальная защита предмета» и никогда не
складывается с `+43 to maximum Energy Shield`.

## Сопротивления: до капа и после

Движок отдаёт два набора полей:

- `*ResistTotal` — после штрафа акта, **до** капа;
- `*Resist` — после капа (75%).

В отчёте показываются оба. В оценку идёт изменение **после капа**: сопротивление
сверх 75% ничего не даёт, поэтому «+40% огня» при уже закрытом огне не улучшает
итог — вместо этого появляется предупреждение «уже на капе». Хаос штрафом акта не
затрагивается.

Если движок недоступен, сопротивления проецируются от
`calculated.resistance_baseline` профиля: база «до капа» + изменение от предмета,
затем штраф сценария и кап. Проекция помечена `declared`, а не `engine`.

## Оценка

Оценка — не игровой расчёт, а сумма вкладов по фиксированным весам. Веса и
пороги зафиксированы в `poe2cc/gear/rating.py` и меняются только вместе с тестами.

| Что | Вес на единицу |
|---|---|
| Здоровье | 0.5 |
| Энергетический щит | 0.35 |
| Мана | 0.1 |
| Броня / уклонение | 0.08 |
| Порог оглушения | 0.02 |
| Сопротивление после капа | 3.0 за 1 п.п. |
| Скорость передвижения | 0.6 за 1 п.п. |
| EHP (относительное изменение) | 0.5 за 1% |
| TotalDPS (относительное изменение) | 0.5 за 1% |

Пороги: `>= +3` — улучшение, `<= -3` — ухудшение, между — «примерно то же самое».
Вердикты `not_equippable` (надеть нельзя) и `inconclusive` (не хватает данных)
перекрывают балл. Если оценка неполная, дополнительно показывается
`provisional_verdict` — но итоговый вердикт остаётся `inconclusive`.

## CLI

```bash
# полный отчёт по тексту предмета
uv run python scripts/gear_analyze.py --slot Boots --item-text candidate.txt

# по структурированному JSON + сохранить JSON-отчёт
uv run python scripts/gear_analyze.py --slot Boots \
    --item-json data/candidates/sinkov-boots-windrush-partial.json \
    --json .tmp-bootstrap/report.json

# только объявленные свойства, без движка
uv run python scripts/gear_analyze.py --slot Boots --item-json cand.json --no-engine

# другой сценарий профиля
uv run python scripts/gear_analyze.py --slot Boots --item-json cand.json \
    --scenario endgame-pinnacle-as-imported
```

Коды возврата: `0` — отчёт построен, `1` — ошибка входных данных, `2` — движок
недоступен или вернул ошибку, `3` — предмет нельзя надеть.

## Режимы работы

| `mode` | Когда | Что посчитано |
|---|---|---|
| `engine` | движок отработал | всё: характеристики, сопротивления, EHP, DPS |
| `declared_only` | движок недоступен, отключён или предмет нельзя воспроизвести | аддитивные модификаторы и проекция сопротивлений |

Переход в `declared_only` — не ошибка, а честное ограничение: отчёт объясняет
причину и перечисляет, что осталось неизвестным.

## Безопасность работы с билдом

1. Исходный XML читается один раз и хешируется (`sha256`).
2. Копия кладётся во временный каталог `poe2cc-gear-*`.
3. Движок загружает **копию**, эксперимент выполняется только в ней.
4. Каталог удаляется в `finally`, факт удаления фиксируется в отчёте
   (`temp_copy_removed`).
5. sha256 пересчитывается после анализа: `unchanged: false` делает результат
   недостоверным.

Экспериментальные предметы в исходный XML не записываются никогда.

## Тесты

```bash
uv run pytest tests/ -q                       # 115 тестов
uv run pytest tests/ -q -m integration        # 7 тестов с настоящим PoB2
uv run pytest tests/test_gear_analyzer.py -q  # обязательные сценарии S5.1
```

Обязательные сценарии закреплены в `tests/test_gear_analyzer.py`:

1. предмет выше уровня персонажа;
2. недостаточные атрибуты;
3. потеря сопротивления при замене ботинок;
4. превышение капа сопротивлений;
5. смена типа защиты (ES → броня);
6. нераспознанный модификатор;
7. связанные бонусы против объявленного итога;
8. движок недоступен;
9. ошибка расчёта;
10. исходный XML не изменён (и временная копия удалена);
11. сравнение двух предметов при одинаковой конфигурации монстра.

Интеграционные тесты (`tests/test_gear_integration.py`) проверяют на настоящем
PoB2: версию движка, совпадение базы с профилем (жизнь 947, ES 238, броня 300),
нулевую разницу для того же предмета, неизменность XML и реального кандидата.
