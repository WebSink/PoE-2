# Архитектура PoE 2 Control Center

Статус: **bootstrap**. Здесь зафиксированы границы модулей и контракты данных,
а не реализация приложения.

## Принципы

1. **Локально и просто.** Один репозиторий, файлы JSON/Markdown, никаких Docker,
   БД и облачных сервисов на этом этапе.
2. **Детерминированные расчёты — кодом.** Сравнение предметов, дельты
   сопротивлений и требований считает скрипт, а не LLM.
3. **LLM — для объяснений.** A6-модели классифицируют, суммируют и объясняют
   готовые числа; они не являются источником игровых значений.
4. **Источник истины — PoB2-движок.** Реальные DPS/EHP/защита берутся только из
   `pob-mcp` (headless Path of Building 2). Профиль из скриншотов — вспомогательный.
5. **Явная неопределённость.** У каждого факта есть статус: подтверждён,
   не подтверждён, устарел, неизвестен.

## Поток данных

```
Скриншоты / ручной ввод / PoB .xml
        │
        ▼
[1] Character Profile  ──►  data/characters/*.json
        │                        │
        │                        ├──► [2] Gear Analyzer (детерминированный diff)
        │                        │
        │                        └──► [3] PoB2 Engine Adapter (MCP)
        │                                   │
        │                                   ▼
        │                            реальные stats / DPS / EHP
        │
        ├──► [4] Market Assistant (ручные объявления + фильтры)
        │
        ├──► [5] AI Advisor (A6: объяснение, приоритеты)
        │
        └──► [6] Upgrade History (append-only JSONL)
```

## Модули

### 1. Character Profile

- Вход: `data/characters/<id>.json` (`schema_version` 2.0.0).
- Задачи: валидация схемы, нормализация слотов, явное разделение уровней
  достоверности: `observed` / `imported` / `calculated` / `unverified`.
- Не делает расчётов урона.
- Контракт: неизменяемый снимок + метка источника и даты. Новые снимки — новые
  записи/версии (`data/characters/history/`), а не молчаливая перезапись.
- Расчётные величины существуют только внутри `calculated.scenarios[*]` вместе с
  конфигурацией, её обоснованием и датой снятия.
- Проверки: `scripts/validate_data.py` (схема + доменные правила, только stdlib) и
  `tests/test_character_profiles.py` (те же правила + негативные кейсы).
- Описание модели: `docs/character-profile-schema.md`.

### 2. Gear Analyzer

- Вход: текущий предмет слота + кандидат(ы).
- Выход: таблица «получено / потеряно / итог» по: здоровью, ES, броне,
  уклонению, сопротивлениям, атрибутам, скорости передвижения, требованиям.
- Обязательно учитывает: требование уровня, требования атрибутов, заменяемый слот,
  потерю резистов и ES, caps сопротивлений.
- Цены и доступность не входят в модуль — это Market Assistant.

### 3. PoB2 Engine Adapter

- Реализация: MCP `pob-mcp` → `luajit` → Path of Building 2 (release v0.23.1).
- Вход: PoB build code / `.xml` / URL (pobb.in и т.п.).
- Выход: stats из движка (`get_stats`), дерево (`get_tree_state`), камни
  (`get_skills`), предметы (`get_items`), sanity check.
- Любой результат расчёта обязан нести конфигурацию: штраф сопротивлений, уровень
  и тип цели, броня/уклонение/сопротивления врага. Без конфигурации число недействительно.
- Импорт приходит с эндгейм-дефолтами (`-60` / уровень 82 / броня 8063) — для кампании
  их надо переопределять.
- Ограничение: **без PoB-экспорта Sinkov расчёт невозможен**; JSON-профиль не
  импортируется как билд.
- Не пишет в установку PoB2; только читает данные.

### 4. Market Assistant

- Вход: вручную вставленные объявления или подготовленные фильтры.
- Выход: нормализованная таблица предложений, проверка лиги/валюты/цены,
  сравнение с текущим предметом.
- Запрещено: скрапинг, недокументированные API, обход защиты, автосделки,
  сообщения продавцам.

### 5. AI Advisor

- Вход: компактный контекст (профиль + дельта предметов + stats PoB2).
- Выход: приоритеты апгрейдов, объяснение, риски.
- Модели: см. `docs/integrations/a6-model-routing.md`.
- Не получает весь репозиторий и не генерирует игровые числа «из головы».

### 6. Upgrade History

- Формат: append-only `data/history/<character>.jsonl`.
- Запись: дата, слот, было/стало, источник данных, дельта подтверждённых статов.
- Позволяет откатить рекомендацию и увидеть фактический эффект.

## Предлагаемая структура репозитория (по мере роста)

```
data/

  characters/history/  # неизменяемые прошлые снимки
  schemas/             # JSON Schema профилей
  history/             # JSONL история апгрейдов
  market/              # сохранённые вручную объявления/фильтры
  builds/              # локальные PoB2-экспорты (в Git не входят)
docs/
  architecture.md
  character-profile-schema.md
  integrations/
skills/
  poe2-build-analysis/
  poe2-gear-optimizer/
  poe2-market-research/
  poe2-development/
config/
  mcp.example.json
  model-routing.example.json
scripts/
  check-pob.ps1
  validate_data.py     # валидатор профилей (stdlib)
tests/
  test_character_profiles.py
src/                   # появится на этапе реализации
  character/
  gear/
  pob/
  market/
  advisor/
```

## Технологический выбор

- **TypeScript** — UI/CLI и типизированные контракты данных (будущее).
- **Python** — быстрые скрипты анализа и обвязка PoB2 (уже используется pob-mcp).
- **JSON Schema** — валидация профилей и истории.
- **Без Docker/БД** — до появления реальной необходимости.
