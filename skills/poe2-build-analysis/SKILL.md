# PoE 2 Build Analysis

## Когда применять

- Нужно разобрать персонажа по профилю `data/characters/*.json` или PoB-экспорту.
- Нужно оценить защиту (жизнь, ES, броня, уклонение, блок, сопротивления).
- Нужно проверить дерево пассивок и связки камней.
- Нужно объяснить, какие показатели подтверждены, а какие устарели.

Не применять для сравнения конкретных предметов (это `poe2-gear-optimizer`) и для
поиска объявлений (это `poe2-market-research`).

## Входы

1. `data/characters/<name>.json` — профиль (schema_version 1.0.0).
2. PoB build code / `.xml` / ссылка pobb.in — если есть.
3. MCP `pob-mcp` — реальные расчёты движка.
4. Скриншоты — только как подтверждение, с датой.

## Обязательный порядок

1. **Определи версию данных.** PoB2 v0.23.1 грузит tree data `0_5`. Указать
   версию игры/движка рядом с выводами.
2. **Проверь профиль.** Валидность JSON, `source.compiled_date`, поле
   `verification`, `comparison_items_not_confirmed_equipped`.
3. **Раздели факты:**
   - подтверждено снимком;
   - подтверждено PoB-экспортом;
   - не подтверждено / устарело / неизвестно.
4. **Проверь защиту по порогам:**
   - сопротивления до/после caps (огонь/холод/молния, хаос отдельно);
   - эффективный пул жизни (Life + ES), реген/реcharge;
   - слои: броня, уклонение, блок, обереги;
   - движение (штраф скорости — критичен для кампании).
5. **Проверь урон только через движок.** Если PoB-билда нет — писать
   «расчёт недоступен», а не оценку.
6. **Дерево и камни.** Без экспорта дерева не предлагать точечный сброс очков.
   Названия поддержек по иконкам не угадывать.
7. **Сформулируй 3–5 приоритетов** с ожидаемым эффектом и способом проверки.

## Жёсткие правила

- Отображаемый DPS разных умений в игре **не сопоставим** (смешаны DPS и разовый
  урон). Не строить по нему рейтинг умений.
- Не выдавать `displayed_dps` за расчёт PoB.
- Не считать неподтверждённый нагрудник надетым.
- Каждое игровое утверждение — с источником (PoB2-движок / официальная
  документация / подтверждённый снимок) и версией.
- Не предлагать покупки без рыночной проверки.

## Инструменты

- `pob-mcp`: `load_build`, `get_stats`, `get_character`, `get_tree_state`,
  `get_skills`, `get_items`, `sanity_check`, `search_tree`, `list_valid_supports`.
- Локально: чтение JSON, детерминированные скрипты, без внешних API.
