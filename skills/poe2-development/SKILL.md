# PoE 2 Development

## Когда применять

- Любая правка кода, конфигурации или скриптов в `C:\Projects\PoE-2`.
- Подготовка коммита/PR.
- Добавление зависимости или интеграции.

## Базовые правила

1. **Сначала состояние репозитория.** `git status`, ветка, remote, HEAD SHA.
   Не считать чужие незакоммиченные файлы своими.
2. **Ветка под задачу.** `feat/...`, `fix/...`, `chore/...`, `docs/...`.
   Прямые коммиты в `main` и merge — только владелец.
3. **Минимальный diff.** Не рефакторить попутно, не переписывать чужие файлы.
4. **Проверка перед коммитом:** тесты/линт/скрипт проверки, `git diff`,
   отсутствие секретов и `.tools/`.
5. **Секреты** — только в Cherry Studio / gh keyring. В коде и логах их нет.
6. **Зависимости** — только проверенные источники, фиксировать версии,
   объяснять необходимость. Не добавлять Docker/БД без реальной нужды.

## TypeScript

- `strict: true`, явные типы на границах модулей, без `any` без причины.
- Данные персонажа/предметов — через типы и runtime-валидацию (JSON Schema/zod).
- Чистые функции для расчётов; побочные эффекты — в адаптерах.
- Ошибки не глотать: возвращать типизированный результат.

## Python

- Python 3.12+, `uv` для окружений.
- Типизация (`from __future__ import annotations`), `ruff`/`pytest`.
- Скрипты детерминированные, без сетевых вызовов по умолчанию.
- Не менять `.tools/pob-mcp` — это вендорная копия; обновление отдельной задачей.

## Тесты

- Расчёты предметов и caps сопротивлений — unit-тесты на граничные случаи.
- Интеграция PoB2: `scripts/check-pob.ps1` и
  `uv run pytest tests/test_bridge_protocol.py` в `.tools/pob-mcp`.
- Не заявлять «тесты прошли», если они не запускались.

## Git / PR

```bash
git status
git diff
git add <files>
git commit -m "feat(scope): ..."
git push -u origin <branch>
gh pr create --draft --base main --head <branch>
```

- Draft PR, без merge.
- В описании PR: что сделано, как проверено, что не проверено.
- Не использовать `--force`, `reset --hard`, `clean`, `stash` без разрешения.

## Definition of Done

- [ ] Изменения соответствуют задаче.
- [ ] Тесты/проверки выполнены и их результат приложен.
- [ ] Нет секретов, больших бинарников и `.tools/`.
- [ ] Документация обновлена, если изменились контракты.
- [ ] Указано, что осталось непроверенным.
